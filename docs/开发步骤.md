## 1. 项目目标

做一个模仿原神任务界面的 PC 单机日程软件，核心能力：

- 以“本周任务”为主视图；
- 支持当天及更长时间的日程、每日重复日程；
- 到点自动提醒，可设置提前提醒；
- 任务手动完成，维护完成状态；
- 每周统计任务数量和完成数；
- 最多可设置 10 个每日委托，每天从委托池中随机出现 4 个；
- 重要任务可置顶，置顶只在同类任务内生效；
- 全局只能追踪一个任务，追踪任务显示在任务栏最顶部；
- 任务可归入任务夹，任务夹可命名、设重要/次要、在右侧放静态图片；
- 支持任务导入导出和本地备份；
- 不接云端，不依赖网络。

第一版只做 Windows 端。数据层和通知层保留平台抽象，后续如果要加 Android，不需要重写业务核心。

### 3.1 整体布局

截图里是三块结构，第一版严格保留：

```text
┌──────┬──────────────────────────────┬────────────────────────────────┐
│ 5个  │ 任务栏                        │ 详情页                          │
│ 图标 │ ★ 追踪目标                    │ 标题栏：任务标题        [完成]  │
│      │   任务 A（追踪中）             │ 时间 · 地点                     │
│  1   │ ────────────────────────────  │ ──────────────────────────────  │
│  2   │ 本周全部任务                   │ 任务名称                        │
│  3   │   重要任务夹  ▸      [图片]    │ 具体介绍和内容……                │
│  4   │     任务 B   10:00            │                                │
│  5   │   次要任务夹  ▸      [图片]    │                                │
│      │   每日委托    2/4             │ 专注模式 [开关]      追踪目标   │
│      │   单独任务                     │                                │
│      │ 任务总览                      │                                │
└──────┴──────────────────────────────┴────────────────────────────────┘
```

### 3.2 最左侧 5 个按钮

保持截图里的图标外观，鼠标悬停显示名称。

| 顺序 | 功能 | 任务栏内容 |
|---|---|---|
| 1 | 本周全部任务 | 聚合视图，按重要任务夹 → 次要任务夹 → 每日委托 → 单独任务排列 |
| 2 | 重要任务夹 | 设为“重要”、且含本周任务的任务夹 |
| 3 | 次要任务夹 | 设为“次要”、且含本周任务的任务夹 |
| 4 | 每日委托 | 从最多 10 个委托池中随机出现 4 个 |
| 5 | 单独任务 | 没有归入任务夹的任务 |

当前设计假设：

- 第 1 个按钮是聚合视图，不再额外重复一份“本周全部”分组。
- 顶部“追踪目标”是独立的跨类分组，位于这 5 个视图之上。

### 3.3 任务栏

任务栏包含任务夹和任务，显示名称与时间。

任务夹行：

```text
▸ 重要任务夹                本周 3      [右侧静态图片]
```

- 只显示包含本周任务的任务夹。
- 右侧显示静态图片，GIF 和动图不允许。
- 不提供颜色设置，左侧不显示颜色标记。
- 任务夹可以展开/收起。

任务行：

```text
◆ 任务名称                    10:00
```

- 显示任务名称和时间。
- 今天的任务加“今天”标记，排在同类任务前面。
- 已完成任务置灰、打勾，排在自己所属分类的底部。

选中状态：

- 任务卡使用羊皮纸底色、金色描边、轻微外发光；
- 所属任务夹标题同步高亮；
- 选中行左侧出现白色小三角箭头；
- 如果任务在收起的任务夹里，自动展开父任务夹；
- 详情页切换使用 150–200ms 淡入。

### 3.4 详情页

从上到下：

1. 标题栏：任务标题，右侧“完成”按钮；
2. 子标题：时间 · 地点；
3. 正文第一行：任务名称；
4. 正文下方：具体介绍和内容；
5. 底部：左侧“任务总览”、中间“任务专注模式”开关、右侧“追踪目标”。

标题与名称：

- `name`：任务名称，必填，任务栏和正文第一行使用；
- `title`：任务标题，选填；
- `title` 为空时，标题栏显示 `name`；
- 两者不同时，标题栏显示 `title`，正文第一行仍显示 `name`。

示例：

```text
名称：去璃月港送信
标题：送信

标题栏：送信
正文第一行：去璃月港送信
```

### 3.5 任务专注模式

- 底部有一个拨动开关。
- 打开后，用约 400ms 的淡入 + 轻微缩放，弹出居中确认弹窗，背景变暗。
- 功能暂未定义，第一版只做界面占位：
  - 显示“专注模式”标题和说明文字；
  - 有“取消 / 确定”；
  - 不启动计时；
  - 不阻止提醒；
  - 不写入业务数据。
- 关闭弹窗后，开关回到关闭状态，避免用户误以为功能已生效。

### 3.6 任务总览

点击任务栏左下角“任务总览”打开全窗口面板：

- 顶部：过去 / 本周 / 未来 / 全部；
- 左侧：选择具体某一周；
- 中间：该周任务列表；
- 右侧：本周统计；
- 点击任务可关闭面板并回到主界面选中它。

统计内容：

- 本周应完成任务数；
- 已完成数；
- 完成率；
- 每天完成柱状图；
- 按任务夹、委托、单独任务分类的分布。

## 4. 业务规则

### 4.1 本周范围

默认：

```text
周一 04:00 → 下周一 04:00
```

设置可改为：

```text
周一 00:00 → 下周一 00:00
```

规则：

- 04:00 模式下，周一 00:00–03:59 仍属于上一周；
- 任务按 occurrence 的开始时间归属周；
- 跨周任务在涉及的两周都可见，但统计只算开始周；
- 主界面“本周任务”和任务总览共用同一套周界；
- 修改周界后立即重新计算，不做数据迁移。

### 4.2 任务分类

| 类型 | 判定 |
|---|---|
| 重要任务夹中的任务 | `folder_id` 指向 importance=important 的任务夹 |
| 次要任务夹中的任务 | `folder_id` 指向 importance=secondary 的任务夹 |
| 每日委托 | 独立 commissions 表 |
| 单独任务 | `folder_id` 为空的其他任务 |

没有归类的任务自动进入“单独任务”，不再有“未分类任务夹”。

### 4.3 排序

任务栏顶部：

```text
★ 追踪目标（0 或 1 条）
```

下面按当前视图分组。

分组内顺序：

```text
未完成任务：
  置顶任务（pinned_at 从早到晚）
  手动排序 / 普通任务

已完成任务：
  该组最底部
  按 completed_at 倒序，最近完成的在最上面
```

说明：

- 多个置顶按置顶操作时间从早到晚，最早的在上；
- 已完成任务不参与置顶和手动拖拽；
- 置顶时间保留，任务完成期间不生效，撤销完成后恢复原位置；
- 已完成任务仍保留在所属分类内，不合并到全局“已完成”区；
- 任务夹内的任务落在该任务夹底部；
- 委托完成后落在委托组底部；
- 单独任务完成后落在单独任务组底部。

示例：

```text
重要任务夹
  任务 C        置顶时间 11/18，最早置顶 → 最上面
  任务 B        置顶时间 11/19
  任务 A        普通任务
  ────────────
  任务 D        11/20 完成 → 已完成区最上面
  任务 E        11/19 完成
  任务 F        11/18 完成 → 最下面
```

### 4.4 置顶

- 只允许在同一类型、同一任务夹内置顶；
- 置顶项按 `pinned_at ASC` 排序；
- 手动排序使用 `manual_order`；
- 置顶组始终在未置顶任务前；
- 提供“恢复默认排序”。

### 4.5 追踪目标

- 全局同一时间只能追踪一个任务；
- 追踪任务显示在任务栏最顶部的独立分组；
- 可以跨类，不受同类置顶限制；
- 新增任务时可以设置“设为追踪目标”；
- 编辑任务时可以修改；
- 详情页右下角“追踪目标”按钮也可以切换；
- 已有追踪任务时，设置新任务会弹确认，替换旧追踪目标；
- 删除被追踪任务时，追踪状态自动清空；
- 追踪任务在原来的任务夹/分组中保留一份，并标记“追踪中”；
- 如果追踪任务属于任务夹，同时把该任务夹在所属重要/次要组内置顶，任务本身也在任务夹内置顶；
- 已完成但仍在追踪中的任务，继续显示在顶部追踪组，置灰打勾，直到手动取消追踪。

数据库层要对“唯一追踪”做约束，不能只靠界面限制。

### 4.6 任务夹

任务夹设置入口：

1. 选中任务夹内的任意任务；
2. 任务栏顶部出现当前任务夹标题；
3. 点击该标题进入设置。

设置项：

- 名称；
- 重要 / 次要；
- 右侧静态图片上传、替换、删除；
- 删除任务夹。

规则：

- 只支持静态图，拒绝 GIF、动态 WebP；
- 不提供颜色设置，左侧无颜色标记；
- 删除任务夹后，其中的任务自动变为“单独任务”，不跟着删除；
- 任务夹只有包含本周任务时才出现在任务栏；
- 空任务夹可通过任务总览中的历史/未来任务进入，或后续增加“任务夹管理”入口。

### 4.7 每日委托

- 委托池最多 10 个，超过禁止新增；
- 每天固定时间重置，默认 04:00，可配置；
- 每天重置时，从启用的委托池中随机抽取 4 个，生成当天委托；
- 池中不足 4 个时全部出现；池为空时显示空状态；
- 当天抽取结果只生成一次，重开软件、切换视图、刷新都不重新抽；
- 设置入口与任务夹一致：选中今天任意一个委托，点击顶部的“每日委托”标题进入设置；
- 顶部标题旁额外提供一个齿轮图标，委托池为空时也能进入设置；
- 设置界面管理最多 10 个委托池任务：新增、编辑、启用/停用、删除、排序；
- 设置界面同时显示今天抽中的 4 个和未抽中的池任务；
- 重置后第一次打开软件弹出“今日委托”弹窗，只显示当天抽中的 4 个；
- 如果软件正在运行，到点也可以弹出；
- 后台运行时发一条汇总通知“今日委托已刷新”，不要发 4 条；
- 未完成不结转，按当天未完成记录；
- 完成的委托在委托组底部，按完成时间倒序；
- 删除或停用池任务不影响已经生成的当天实例，实例保存当时的标题、地点和描述快照。

随机策略第一版采用“每天独立均匀随机”，允许不同日期抽到相同组合；暂不做权重、避免连续重复等复杂规则。

### 4.8 完成状态

- 完成后手动点击完成；
- 完成记录绑定到 occurrence / commission_instance，不完成整个任务模板；
- 完成后取消剩余提醒；
- 已完成任务置灰、打勾、可点开详情、可撤销完成；
- 周统计实时更新；
- 撤销完成后回到原来的置顶/手动位置。

### 4.9 提醒

提前量：

```text
准时 / 5 分钟前 / 30 分钟前 / 1 小时前 / 1 天前 / 3 天前 / 1 周前
```

可多选。重复周期：

```text
不重复 / 每天 / 每周 / 每月 / 每年
```

说明：

- 提前量最多到 1 周，不再提供“提前一个月 / 一年”；
- “每月 / 每年”只作为重复周期，不再作为提前提醒；
- 这样避免提醒过早，也避免本周任务栏被远期提醒撑得臃肿；
- 提前量对应的分钟数：`0 / 5 / 30 / 60 / 1440 / 4320 / 10080`。

Windows 端：

- 使用本地 Toast 通知；
- 软件关闭窗口后默认隐藏到托盘，保持调度进程存活；
- 开机自启；
- 睡眠唤醒后补查错过的提醒，只发一条汇总，避免轰炸；
- 用户完全退出程序时提示“退出后提醒将停止”。

### 4.10 导入导出

导出文件：`.gtsk`，本质是 ZIP：

```text
manifest.json   版本、导出时间、设备信息
data.json       任务、任务夹、委托、设置
images/         任务夹图片
```

导入流程：

1. 校验格式和版本；
2. 显示预览：任务数、任务夹数、图片数；
3. 自动备份当前数据；
4. 选择“全部替换”或“合并”；
5. 合并按 UUID + `updated_at` 去重，冲突列出让用户选择。

无云端，两台设备各自独立；换设备或备份靠这个文件手动传输。

- 每天自动备份数据库。

## 6. 关键算法

### 6.1 计算本周范围

```python
def week_range(now, boundary_hour):
    # 找到最近的周一 00:00
    monday = (now - timedelta(days=now.weekday())).replace(
        hour=0, minute=0, second=0, microsecond=0
    )
    start = monday.replace(hour=boundary_hour)
    if now < start:
        start -= timedelta(days=7)
    end = start + timedelta(days=7)
    return start, end
```

必须测试：

- 周一 00:00；
- 周一 03:59；
- 周一 04:00；
- 周日 23:59；
- 修改为 00:00 周界后的同一批时间点。

### 6.2 排序查询

同一任务夹/同一分组内：

```text
1. 未完成任务
   1.1 置顶：pinned_at ASC
   1.2 非置顶：manual_order ASC，其次时间
2. 已完成任务
   2.1 completed_at DESC
```

已完成任务不参与置顶和手动排序。

### 6.3 追踪替换

设置新追踪任务时，在同一个数据库事务里：

1. 清除旧任务的 `is_tracked` / `tracked_at`；
2. 设置新任务；
3. 如果新任务属于任务夹，设置任务夹置顶；
4. 如果旧任务的置顶来源是 track，清除对应置顶；
5. 提交。

### 6.4 委托每日重置与随机抽取

- 根据 `commission_reset_hour` 计算当前委托日；
- 先查 `commission_days`，如果当天已有记录，直接使用已生成的实例，不重抽；
- 如果没有记录，读取所有启用的委托池任务；
- 用 `random.SystemRandom().sample` 抽取 `min(4, 池数量)` 个；
- 为抽中的委托写入 `commission_instances`，同时保存名称、标题、地点、描述快照；
- 写入 `commission_days(drawn_at)`，保证当天只抽一次；
- 第一次进入软件时检查 `popup_shown_at`，没弹过则弹窗，只显示当天 4 个；
- 弹窗后记录 `popup_shown_at`；
- 池为空时也写入 `commission_days`，显示空状态，避免反复检查；
- 已完成实例不结转。

随机抽取必须持久化，不能每次打开界面都重新随机，否则用户会看到委托列表变化。

### 6.5 周统计

- 分母：本周应发生的 occurrence 数；
- 分子：本周应发生且已完成的 occurrence 数；
- 完成率 = 分子 / 分母；
- 上周任务本周补做，单独显示“本周补完成”，不计入分母；
- 委托单独统计，也可合并展示；
- 按天完成数、按任务夹分布从 occurrence 聚合。

## 10. 风险和对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Windows 通知在程序退出后失效 | 漏提醒 | 关闭窗口隐藏到托盘；退出时明确提示；启动时补查 |
| Flet 自定义视觉受限 | 不够像原神 | 用背景图、Container、自绘图标组合；先做原型确认 |
| SQLite 周界和月末/年末边界 | 统计错 | 周界函数单测；使用本地时区；避免手写日期计算 |
| 追踪和置顶规则冲突 | 排序混乱 | 追踪独立顶部组；普通置顶只在本类；`pin_source` 区分来源 |
| 已完成任务排序和手动排序冲突 | 用户困惑 | 已完成区固定按完成时间倒序，不参与手动排序 |
| 无云端导致设备数据不一致 | 统计不一致 | 明确手动导入导出；导入前备份；合并按 UUID |
| 直接使用游戏素材 | 版权风险 | 只借鉴布局和配色；图标、背景、字体使用原创或开源资源 |
| 第一版范围膨胀 | 延期 | 冻结 v1 范围；Android、云同步、标签、月历、小组件全部后置 |
