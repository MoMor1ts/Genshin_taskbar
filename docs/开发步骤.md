## 1. 项目目标

做一个模仿原神任务界面的 PC 单机日程软件，核心能力：

- 以“本周任务”为主视图；
- 支持当天及更长时间的日程、每日重复日程；
- 到点自动提醒，可设置提前提醒；
- 任务手动完成，维护完成状态；
- 每周统计任务数量和完成数，周总结带角色评论；
- 每日委托池由“默认角色委托 + 自定义委托”组成，每天随机出现 4 个；
- 完成委托获得积分，积分可刷新当日委托或一键完成；
- 重要任务可置顶，置顶只在同类任务内生效；
- 全局只能追踪一个任务，追踪任务显示在任务栏最顶部；
- 任务可归入任务夹，任务夹可命名、设重要/次要，并从默认 tag 中选择封面图；
- 原“小任务”改名“世界任务”，保留本地功能；后续增加联网任务板；
- 支持任务导入导出和本地备份；
- v1 不依赖网络；v2 任务板需要账号、服务器和内容审核。

第一版只做 Windows 本地端。数据层和通知层保留平台抽象，后续如果要加 Android，不需要重写业务核心。v2 联网任务板单独立项，不与 v1 抢工期。

## 2. 技术选型

| 模块 | 选型 | 说明 |
|---|---|---|
| 语言 | Python 3.12 / 3.13 | 当前机器是 3.14.3，开始前先用 `uv` 建一个 Flet 稳定支持的虚拟环境并锁版本 |
| UI | Flet | Python 写界面，Flutter 渲染；适合做三栏、动画、响应式 |
| 数据 | SQLite | 本地单文件数据库，Python 内置 `sqlite3` |
| 通知 | `flet-notifications` | Windows 本地 Toast，支持定时通知 |
| 测试 | pytest | 核心规则、周界、排序、积分、导入导出 |
| 打包 | `flet build windows` | 生成 Windows 可执行程序；需要 Visual Studio C++ ATL |
| 版本管理 | Git | 本地仓库即可 |
| v2 服务端 | FastAPI + PostgreSQL + Redis | 账号、积分账本、任务板、审核队列；仅 v2 使用 |
| v2 管理端 | 简单 Web 后台 | 人工审核、举报处理、任务下架 |

本地数据目录：

```text
%APPDATA%\GenshinTaskbar\
  app.db
  backups\
```

tag 封面和角色头像随应用内置，不写入用户数据目录，也不允许用户自定义上传。

原则：

- v1 不申请网络权限，不做云同步；
- v1 的数据全部在本地，导出文件不包含用户上传图片；
- 每次启动做一次本地自动备份，保留最近 7 份；
- v2 才引入账号、服务器、联网任务板和内容审核。

## 3. 界面结构

### 3.1 整体布局

截图里是三块结构，第一版严格保留：

```text
┌──────┬──────────────────────────────┬────────────────────────────────┐
│ 5个  │ 任务栏                        │ 详情页                          │
│ 图标 │ ★ 追踪目标                    │ 标题栏：任务标题        [完成]  │
│      │   任务 A（追踪中）             │ 时间 · 地点                     │
│  1   │ ────────────────────────────  │ ──────────────────────────────  │
│  2   │ 本周全部任务                   │ 任务名称                        │
│  3   │   重要任务夹  ▸      [tag图]   │ 具体介绍和内容……                │
│  4   │     任务 B   10:00            │                                │
│  5   │   次要任务夹  ▸      [tag图]   │                                │
│      │   每日委托  2/4   积分 3       │ 专注模式 [开关]      追踪目标   │
│      │   世界任务                     │                                │
│      │ 任务总览                      │                                │
└──────┴──────────────────────────────┴────────────────────────────────┘
```

### 3.2 最左侧 5 个按钮

保持截图里的图标外观，鼠标悬停显示名称。

| 顺序 | 功能 | 任务栏内容 |
|---|---|---|
| 1 | 本周全部任务 | 聚合视图，按重要任务夹 → 次要任务夹 → 每日委托 → 世界任务排列 |
| 2 | 重要任务夹 | 设为“重要”、且含本周任务的任务夹 |
| 3 | 次要任务夹 | 设为“次要”、且含本周任务的任务夹 |
| 4 | 每日委托 | 默认角色委托 + 自定义委托，每天随机出现 4 个；完成得积分 |
| 5 | 世界任务 | 没有归入任务夹的本地任务；v2 增加联网任务板 |

当前设计假设：

- 第 1 个按钮是聚合视图，不再额外重复一份“本周全部”分组。
- 顶部“追踪目标”是独立的跨类分组，位于这 5 个视图之上。

### 3.3 任务栏

任务栏包含任务夹和任务，显示名称与时间。

任务夹行：

```text
▸ 重要任务夹                本周 3      [tag 图]
```

- 只显示包含本周任务的任务夹。
- 右侧封面从默认 tag 图库中选择，不允许用户上传图片。
- 不提供颜色设置，左侧不显示颜色标记。
- 任务夹可以展开/收起。

任务行：

```text
◆ 任务名称                    10:00
```

- 显示任务名称和时间。
- 今天的任务加“今天”标记，排在同类任务前面。
- 已完成任务置灰、打勾，排在自己所属分类的底部。

选中状态：

- 任务卡使用羊皮纸底色、金色描边、轻微外发光；
- 所属任务夹标题同步高亮；
- 选中行左侧出现白色小三角箭头；
- 如果任务在收起的任务夹里，自动展开父任务夹；
- 详情页切换使用 150–200ms 淡入。

### 3.4 详情页

从上到下：

1. 标题栏：任务标题，右侧“完成”按钮；
2. 子标题：时间 · 地点；
3. 正文第一行：任务名称；
4. 正文下方：具体介绍和内容；
5. 底部：左侧“任务总览”、中间“任务专注模式”开关、右侧“追踪目标”。

标题与名称：

- `name`：任务名称，必填，任务栏和正文第一行使用；
- `title`：任务标题，选填；
- `title` 为空时，标题栏显示 `name`；
- 两者不同时，标题栏显示 `title`，正文第一行仍显示 `name`。

示例：

```text
名称：去璃月港送信
标题：送信

标题栏：送信
正文第一行：去璃月港送信
```

### 3.5 任务专注模式

- 底部有一个拨动开关。
- 打开后，用约 400ms 的淡入 + 轻微缩放，弹出居中确认弹窗，背景变暗。
- 功能暂未定义，第一版只做界面占位：
  - 显示“专注模式”标题和说明文字；
  - 有“取消 / 确定”；
  - 不启动计时；
  - 不阻止提醒；
  - 不写入业务数据。
- 关闭弹窗后，开关回到关闭状态，避免用户误以为功能已生效。

### 3.6 任务总览与每周总结

点击任务栏左下角“任务总览”打开全窗口面板：

- 顶部：过去 / 本周 / 未来 / 全部；
- 左侧：选择具体某一周；
- 中间：该周任务列表；
- 右侧：本周统计 + 每周总结 + 角色评论；
- 点击任务可关闭面板并回到主界面选中它。

统计内容：

- 本周应完成任务数；
- 已完成数；
- 完成率；
- 每天完成柱状图；
- 按任务夹、委托、世界任务分类的分布；
- 每周角色评论。

## 4. 业务规则

### 4.1 本周范围

默认：

```text
周一 04:00 → 下周一 04:00
```

设置可改为：

```text
周一 00:00 → 下周一 00:00
```

规则：

- 04:00 模式下，周一 00:00–03:59 仍属于上一周；
- 任务按 occurrence 的开始时间归属周；
- 跨周任务在涉及的两周都可见，但统计只算开始周；
- 主界面“本周任务”和任务总览共用同一套周界；
- 修改周界后立即重新计算，不做数据迁移。

### 4.2 任务分类

| 类型 | 判定 |
|---|---|
| 重要任务夹中的任务 | `folder_id` 指向 importance=important 的任务夹 |
| 次要任务夹中的任务 | `folder_id` 指向 importance=secondary 的任务夹 |
| 每日委托 | 独立 commissions 表 |
| 世界任务 | `folder_id` 为空的其他本地任务；v2 另增联网任务板来源 |

没有归类的任务自动进入“世界任务”，不再有“未分类任务夹”。

### 4.3 排序

任务栏顶部：

```text
★ 追踪目标（0 或 1 条）
```

下面按当前视图分组。

分组内顺序：

```text
未完成任务：
  置顶任务（pinned_at 从早到晚）
  手动排序 / 普通任务

已完成任务：
  该组最底部
  按 completed_at 倒序，最近完成的在最上面
```

说明：

- 多个置顶按置顶操作时间从早到晚，最早的在上；
- 已完成任务不参与置顶和手动拖拽；
- 置顶时间保留，任务完成期间不生效，撤销完成后恢复原位置；
- 已完成任务仍保留在所属分类内，不合并到全局“已完成”区；
- 任务夹内的任务落在该任务夹底部；
- 委托完成后落在委托组底部；
- 世界任务完成后落在世界任务组底部。

示例：

```text
重要任务夹
  任务 C        置顶时间 11/18，最早置顶 → 最上面
  任务 B        置顶时间 11/19
  任务 A        普通任务
  ────────────
  任务 D        11/20 完成 → 已完成区最上面
  任务 E        11/19 完成
  任务 F        11/18 完成 → 最下面
```

### 4.4 置顶

- 只允许在同一类型、同一任务夹内置顶；
- 置顶项按 `pinned_at ASC` 排序；
- 手动排序使用 `manual_order`；
- 置顶组始终在未置顶任务前；
- 提供“恢复默认排序”。

### 4.5 追踪目标

- 全局同一时间只能追踪一个任务；
- 追踪任务显示在任务栏最顶部的独立分组；
- 可以跨类，不受同类置顶限制；
- 新增任务时可以设置“设为追踪目标”；
- 编辑任务时可以修改；
- 详情页右下角“追踪目标”按钮也可以切换；
- 已有追踪任务时，设置新任务会弹确认，替换旧追踪目标；
- 删除被追踪任务时，追踪状态自动清空；
- 追踪任务在原来的任务夹/分组中保留一份，并标记“追踪中”；
- 如果追踪任务属于任务夹，同时把该任务夹在所属重要/次要组内置顶，任务本身也在任务夹内置顶；
- 已完成但仍在追踪中的任务，继续显示在顶部追踪组，置灰打勾，直到手动取消追踪。

数据库层要对“唯一追踪”做约束，不能只靠界面限制。

### 4.6 任务夹

任务夹设置入口：

1. 选中任务夹内的任意任务；
2. 任务栏顶部出现当前任务夹标题；
3. 点击该标题进入设置。

设置项：

- 名称；
- 重要 / 次要；
- 从默认 tag 图库中选择封面图；
- 删除任务夹。

规则：

- 不再允许用户上传图片，只能从默认 tag 中选择；
- 不提供颜色设置，左侧无颜色标记；
- 删除任务夹后，其中的任务自动变为“世界任务”，不跟着删除；
- 任务夹只有包含本周任务时才出现在任务栏；
- 空任务夹可通过任务总览中的历史/未来任务进入，或后续增加“任务夹管理”入口；
- tag 图库后续也被 v2 任务板用作筛选标签。

### 4.7 每日委托

#### 委托池

委托池由两部分组成：

1. **默认角色委托**：每个自机角色定制 3 个，按角色名义发布，显示角色头像、名字和角色语气；
2. **自定义委托**：用户自行创建，最多 10 个。

规则：

- 每天固定时间重置，默认 04:00，可配置；
- 每天重置时从“默认 + 自定义”池中随机抽取 4 个，生成当天委托；
- **建议默认至少保证 1 个自定义委托**，否则角色默认池很大时，自定义委托几乎抽不到；
- 池中不足 4 个时全部出现；池为空时显示空状态；
- 当天抽取结果只生成一次，重开软件、切换视图、刷新都不重新抽；
- 设置入口与任务夹一致：选中今天任意一个委托，点击顶部的“每日委托”标题进入设置；
- 顶部标题旁额外提供一个齿轮图标，委托池为空时也能进入设置；
- 设置界面分为“默认委托”和“自定义委托”两栏；
- 默认委托只读，可启用/停用，不可修改文案；
- 自定义委托可新增、编辑、启用/停用、删除、排序；
- 重置后第一次打开软件弹出“今日委托”弹窗，只显示当天抽中的 4 个；
- 如果软件正在运行，到点也可以弹出；
- 后台运行时发一条汇总通知“今日委托已刷新”，不要发 4 条；
- 未完成不结转，按当天未完成记录；
- 完成的委托在委托组底部，按完成时间倒序；
- 删除或停用池任务不影响已经生成的当天实例，实例保存当时的标题、地点、描述、角色名和头像快照。

#### 委托积分

- 手动完成 1 个委托，获得 **1 积分**；
- 积分可以累积，不清空；
- 刷新当日委托消耗 **1 积分**；
- 一键完成 1 个委托消耗 **3 积分**；
- 一键完成不返还积分，也不额外获得积分；
- 积分不足以支付时，按钮置灰并显示差距；
- 所有积分变动写入积分流水，便于对账。

#### 刷新规则

- 刷新只替换当天**未完成**的委托；
- 已完成委托保留在原位，不清除；
- 如果当天已完成 N 个，刷新只补抽 `4 - N` 个新委托；
- 刷新后当天仍然是 4 个任务；
- 如果 4 个都已完成，刷新按钮禁用；
- 刷新时排除当天已完成的委托，避免重复出现；
- 刷新消耗 1 积分，不按补抽数量计价。

示例：

```text
当天 4 个委托，已完成 2 个
→ 刷新消耗 1 积分
→ 只重新抽取 2 个未完成槽位
→ 已完成 2 个保留，总数仍是 4 个
```

#### 一键完成规则

- 只能对当天未完成的委托使用；
- 选中一个未完成委托，点击“一键完成”，消耗 3 积分；
- 该委托标记为完成，计入周统计和角色评论；
- 不获得完成积分；
- 已完成或积分不足时按钮禁用。

随机策略第一版采用“每天独立随机，并保证至少 1 个自定义委托”；是否要完全均匀随机，作为待确认项。

### 4.8 完成状态

- 完成后手动点击完成；
- 完成记录绑定到 occurrence / commission_instance，不完成整个任务模板；
- 完成后取消剩余提醒；
- 已完成任务置灰、打勾、可点开详情、可撤销完成；
- 周统计实时更新；
- 撤销完成后回到原来的置顶/手动位置。

### 4.9 提醒

提前量：

```text
准时 / 5 分钟前 / 30 分钟前 / 1 小时前 / 1 天前 / 3 天前 / 1 周前
```

可多选。重复周期：

```text
不重复 / 每天 / 每周 / 每月 / 每年
```

说明：

- 提前量最多到 1 周，不再提供“提前一个月 / 一年”；
- “每月 / 每年”只作为重复周期，不再作为提前提醒；
- 这样避免提醒过早，也避免本周任务栏被远期提醒撑得臃肿；
- 提前量对应的分钟数：`0 / 5 / 30 / 60 / 1440 / 4320 / 10080`。

Windows 端：

- 使用本地 Toast 通知；
- 软件关闭窗口后默认隐藏到托盘，保持调度进程存活；
- 开机自启；
- 睡眠唤醒后补查错过的提醒，只发一条汇总，避免轰炸；
- 用户完全退出程序时提示“退出后提醒将停止”。

### 4.10 世界任务

- 原“小任务 / 单独任务”统一改名为“世界任务”；
- 第 5 个按钮和对应分组都显示“世界任务”；
- v1 仍然是本地任务，保留原来的全部功能；
- 没有归入任务夹的任务自动进入世界任务组；
- 世界任务的排序、置顶、完成、倒序规则不变；
- v2 增加联网任务板后，从任务板接取的任务也进入世界任务组，用“任务板”来源标记区分；
- 本地世界任务和联网世界任务必须能一眼区分，避免混淆。

### 4.11 默认 tag 图库

- 任务夹不再允许自己上传图片；
- 改为从默认 tag 图库中选择一张封面图；
- 每个 tag 包含：名称、静态图片、排序号；

### 4.12 每周角色评论

- 每周总结在统计数据下方增加“角色评论”区块；

### 4.13 v2 联网任务板（后续）

这一节只做规划，不在 v1 开发范围内。

目标：

- 所有人都可以在任务板用积分发布世界任务；
- 其他用户可以接取；
- 完成接取的任务后，获得该任务一定比例的积分；
- 任务按发布积分从大到小排序；
- 支持按 tag 筛选；
- 发布内容经过 AI + 人工审核。

建议流程：

1. 发布者填写标题、说明、tag、悬赏积分、截止时间；
2. 系统扣除并托管悬赏积分；
3. AI 初审，人工复审；
4. 审核通过后上架，按悬赏从高到低排序；
5. 接取者接单，完成后提交完成说明；
6. 发布者确认，或超时自动确认；
7. 接取者获得悬赏的一定比例，剩余部分退回发布者；
8. 出现争议时进入人工处理。

默认规则建议：

- 接取者获得 80%，发布者退回 20%；
- 发布时积分进入托管，不直接打给接取者；
- 超时未确认自动通过；
- 恶意发布、刷分、重复任务、辱骂内容进入审核/封禁；
- 新账号有发布上限和积分上限；
- 任务板积分建议与委托积分分开记账，避免经济互相污染。

技术要求：

- FastAPI + PostgreSQL + Redis；
- 账号系统、积分账本、任务表、接取表、审核队列、举报表；
- 管理后台：人工审核、下架、封禁、争议处理；
- 客户端新增任务板界面；
- 需要内容审核和运营人力，不是纯代码功能。

风险提示：

- “AI + 人工审核”意味着长期运营成本；
- 公开任务板涉及用户隐私、UGC 合规、未成年人保护、举报处理；
- 使用原神角色名、头像和文案做公开联网产品，存在明显版权风险；
- v2 应单独立项，不阻塞 v1 本地版。

### 4.14 导入导出

导出文件：`.gtsk`，本质是 ZIP：

```text
manifest.json   版本、导出时间、设备信息
data.json       任务、任务夹、委托、积分、设置
```

导入流程：

1. 校验格式和版本；
2. 显示预览：任务数、任务夹数、委托数、积分余额；
3. 自动备份当前数据；
4. 选择“全部替换”或“合并”；
5. 合并按 UUID + `updated_at` 去重，冲突列出让用户选择。

说明：

- v1 不包含用户上传图片，tag 图和角色图随应用内置，不进入导出文件；
- v1 无云端，两台设备各自独立；换设备靠文件手动传输；
- v2 的账号、任务板、审核数据不走本地导出。

## 6. 关键算法

### 6.1 计算本周范围

```python
def week_range(now, boundary_hour):
    # 找到最近的周一 00:00
    monday = (now - timedelta(days=now.weekday())).replace(
        hour=0, minute=0, second=0, microsecond=0
    )
    start = monday.replace(hour=boundary_hour)
    if now < start:
        start -= timedelta(days=7)
    end = start + timedelta(days=7)
    return start, end
```

必须测试：

- 周一 00:00；
- 周一 03:59；
- 周一 04:00；
- 周日 23:59；
- 修改为 00:00 周界后的同一批时间点。

### 6.2 排序查询

同一任务夹/同一分组内：

```text
1. 未完成任务
   1.1 置顶：pinned_at ASC
   1.2 非置顶：manual_order ASC，其次时间
2. 已完成任务
   2.1 completed_at DESC
```

已完成任务不参与置顶和手动排序。

### 6.3 追踪替换

设置新追踪任务时，在同一个数据库事务里：

1. 清除旧任务的 `is_tracked` / `tracked_at`；
2. 设置新任务；
3. 如果新任务属于任务夹，设置任务夹置顶；
4. 如果旧任务的置顶来源是 track，清除对应置顶；
5. 提交。

### 6.4 委托每日重置与随机抽取

- 根据 `commission_reset_hour` 计算当前委托日；
- 先查 `commission_days`，如果当天已有记录，直接使用已生成的实例，不重抽；
- 如果没有记录，读取“启用的默认角色委托 + 启用的自定义委托”；
- 建议至少保证 1 个自定义委托：先抽 1 个自定义，再从剩余池补足 3 个；
- 如果自定义池为空，则全部从默认池抽；
- 用 `random.SystemRandom().sample` 抽取，保证不重复；
- 为抽中的委托写入 `commission_instances`，同时保存名称、标题、地点、描述、角色名、角色头像快照；
- 写入 `commission_days(drawn_at)`，保证当天只抽一次；
- 第一次进入软件时检查 `popup_shown_at`，没弹过则弹窗，只显示当天 4 个；
- 弹窗后记录 `popup_shown_at`；
- 池为空时也写入 `commission_days`，显示空状态，避免反复检查；
- 已完成实例不结转。

随机抽取必须持久化，不能每次打开界面都重新随机，否则用户会看到委托列表变化。

### 6.5 完成、刷新与一键完成

#### 手动完成

```text
标记 commission_instance.completed_at
completed_via = manual
写入 point_ledger：+1，reason=complete
写入周统计/角色评论来源
```

#### 刷新

```text
前置：当天未完成数 > 0，积分 >= 1
扣除 1 积分
N = 当天已完成数
需要补抽 4 - N 个
从池中排除当天已完成的 commission_id 和当前未完成实例
写入新的 commission_instances，替换未完成槽位
completed 的实例和位置保持不变
refresh_count += 1
```

#### 一键完成

```text
前置：目标委托未完成，积分 >= 3
扣除 3 积分
标记 completed_at，completed_via = instant
points_awarded = 0
按钮置灰条件：已完成 / 积分不足
```

#### 积分余额

- 不直接存“余额”字段；
- 每次变动写 `point_ledger`，余额 = 该钱包所有 delta 之和；
- 或使用事务内 `balance_after` 做校验，但以流水为准；
- 同一事务内完成“扣积分 + 改状态”，避免扣了积分没完成任务。

### 6.6 周统计

- 分母：本周应发生的 occurrence 数；
- 分子：本周应发生且已完成的 occurrence 数；
- 完成率 = 分子 / 分母；
- 上周任务本周补做，单独显示“本周补完成”，不计入分母；
- 委托单独统计，也可合并展示；
- 按天完成数、按任务夹分布从 occurrence 聚合。

### 6.7 每周角色评论

- 统计本周每个角色对应的已完成委托数；
- 取完成数最高的 1–3 个角色；
- 根据角色 + 成绩选择评论模板；
- 模板占位符填充：`{completed}`、`{rate}`、`{rank}`；
- 用 `week_start + character_id` 做稳定种子，同一周不重复随机；
- 没有委托数据时使用通用旁白；
- v1 不调用 AI，全部本地模板；
- 结果写入 `weekly_summaries.comment_json`，方便历史回看。

## 10. 风险和对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Windows 通知在程序退出后失效 | 漏提醒 | 关闭窗口隐藏到托盘；退出时明确提示；启动时补查 |
| Flet 自定义视觉受限 | 不够像原神 | 用背景图、Container、自绘图标组合；先做原型确认 |
| SQLite 周界和月末/年末边界 | 统计错 | 周界函数单测；使用本地时区；避免手写日期计算 |
| 追踪和置顶规则冲突 | 排序混乱 | 追踪独立顶部组；普通置顶只在本类；`pin_source` 区分来源 |
| 已完成任务排序和手动排序冲突 | 用户困惑 | 已完成区固定按完成时间倒序，不参与手动排序 |
| v1 无云端导致设备数据不一致 | 统计不一致 | 明确手动导入导出；导入前备份；合并按 UUID |
| 默认角色委托内容量巨大 | 内容生产拖期 | 3 个/角色 × 90+ 角色 = 270+ 条；用内容包分批做，先首批角色 |
| 点数值膨胀/刷分 | 经济失衡 | 固定 1 完成=1 积分，刷新 1，一键完成 3；积分流水；v2 分账 |
| 刷新规则歧义 | 少抽/多抽 | 保留已完成，只补抽 4 - N；写死测试用例 |
| 任务板需要服务器和审核 | 范围失控 | v2 单独立项；不在 v1 工期；先明确运营责任人 |
| 公开使用原神角色/素材 | 版权风险 | 个人本地使用与公开发行分开评估；公开版需授权或原创角色 |
| AI + 人工审核成本 | 长期运营压力 | 先小范围内测；审核后台和举报流程同步建设 |
| 第一版范围膨胀 | 延期 | 冻结 v1 范围；Android、账号、联网任务板、月历、小组件全部后置 |

## 12. 待确认事项

开始写代码前，需要确认以下几项。没有确认的，先按“建议默认”执行。

### 必须确认

1. **默认角色委托是覆盖全部自机角色，还是先做一批角色？**  
   如果全部角色 × 3 个，内容量约 270+ 条，且后续还要写角色评论。建议先做首批角色，数据包结构按全量设计。

2. **“默认 + 自定义”的随机比例？**  
   当前建议：有自定义委托时，至少保证 1 个自定义，其余随机。也可以改成完全均匀随机，或设置固定 2 默认 + 2 自定义。

3. **自定义委托上限是否仍是 10 个？**  
   当前按“自定义最多 10 个，默认委托另算”设计。

4. **刷新规则是否按“保留已完成，只补抽 4 - N 个”实现？**  
   当前按这个理解实现，且刷新固定消耗 1 积分。

5. **积分是否永久累积、不清空？**  
   当前按永久累积设计；一键完成不返还、不奖励积分。

6. **v2 任务板是否真的要公开运营？**  
   公开运营需要账号、服务器、AI + 人工审核、举报处理、隐私和版权合规，属于另一套产品。建议 v2 单独立项。

7. **委托积分和任务板积分是否共用同一个钱包？**  
   当前建议分开记账：委托积分用于刷新/一键完成，任务板积分用于发布/接取，避免经济互相污染。

8. **任务板悬赏的结算比例和确认方式？**  
   当前建议接取者获得 80%，发布者退回 20%；发布者确认完成，超时自动确认。需要你确认比例和争议处理方式。

### 可以后置

9. **多日日程的提醒规则？**  
   建议默认：每天固定时间提醒；提前量只挂在开始日，避免“提前一周”在持续期间每天触发。

10. **周统计的“任务数量”口径？**
